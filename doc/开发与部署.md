# 开发、部署与联调

本文说明当前仓库的实际运行方式。协议字段和状态机以[机器人控制台通信协议](机器人控制台通信协议.md)为准；本文件只说明如何把仓库运行起来、如何连接机器人端，以及如何排查常见问题。

## 1. 运行边界

```text
浏览器  ── HTTP / WebSocket ──>  Robot Station 网关  ── TCP / ZRCP/1 ──> 机器人程序
                                      │
                                      └── SQLite：用户、会话、审计、已保存连接
```

- 机器人程序提供 TCP 服务端，网页服务是 TCP 客户端。
- 浏览器只连接网页服务，不直接接触机器人地址、令牌或控制租约。
- `tools/print_robot_receiver.py` 是协议联调接收端，不驱动真机。它会维护内存状态、按约 10 Hz 推送状态、发送动作结果，并在保活超时后停止模拟动作。
- `doc/robot_console_v0.3.html` 是历史界面参考稿，不参与服务运行；实际页面是 `apps/web/public/console.html`。

## 2. 本地开发

需要 Node.js 22 或更高版本，以及 Python 3（仅在运行打印接收端时需要）。

```bash
cp .env.example .env
# 编辑 .env，至少设置随机的 ADMIN_PASSWORD
npm install
npm run dev
```

网页默认地址为 `http://127.0.0.1:8080`。首次启动会创建 SQLite 数据目录和管理员账号。连接机器人有两种方式：

1. 登录后打开“连接设置”，保存并选择一个机器人连接；
2. 在 `.env` 中设置 `ROBOT_HOST`、`ROBOT_PORT`、`ROBOT_TOKEN`，作为启动时的默认连接。

启动时只设置一部分机器人环境变量会被拒绝。令牌保存在网页服务的数据目录，不写入网页文件或浏览器日志。

## 3. 使用打印接收端联调

先启动接收端。机器人端口只需要启动一个监听进程：

```bash
python3 tools/print_robot_receiver.py \
  --host 127.0.0.1 \
  --port 19001 \
  --token test-token
```

再让网页服务连接 `127.0.0.1:19001`。如果通过环境变量连接：

```bash
ROBOT_HOST=127.0.0.1 \
ROBOT_PORT=19001 \
ROBOT_TOKEN=test-token \
npm run dev
```

也可以在网页“连接设置”中保存一条具名连接，再选择并建立连接。

打印接收端的日志是中文摘要，例如：

```text
[RX] 底座前进 0.10 m/s
[TX] 操作成功
[TX] 动作已停止
```

连续动作需要网页持续发送 `motion.keepalive`。按住方向按钮时会持续保活，松开后发送 `motion.stop`；接收端约 750 ms 未收到保活也会自动停止。终端不会打印心跳和保活帧，但它们仍会在协议层正常处理。

## 4. AGX 或普通 Linux 后台运行

下面是一个不依赖 systemd 的最小后台方式。正式部署建议改成 systemd、Docker 或其他进程管理器，并把日志交给统一日志系统。

```bash
mkdir -p ~/.cache/robot-station

nohup python3 tools/print_robot_receiver.py \
  --host 127.0.0.1 \
  --port 19001 \
  --token "$ROBOT_TOKEN" \
  > ~/.cache/robot-station/receiver.log 2>&1 </dev/null &
echo $! > ~/.cache/robot-station/receiver.pid

set -a
. ~/.config/robot-station/agx.env
set +a
npm run build
nohup node apps/server/dist/index.js \
  > ~/.cache/robot-station/agx.log 2>&1 </dev/null &
echo $! > ~/.cache/robot-station/agx.pid
```

检查服务：

```bash
curl -fsS http://127.0.0.1:8088/healthz
tail -f ~/.cache/robot-station/receiver.log
tail -f ~/.cache/robot-station/agx.log
```

如果网页服务端口不是 `8088`，以环境文件中的 `PORT` 为准。`/healthz` 返回 `robot.connected: true` 才表示网关已经完成机器人握手。

## 5. 端口被占用时

不要把端口号当作进程号。先查监听者：

```bash
ss -ltnp | grep ':19001'
```

输出中的 `pid=...` 才是接收端进程号。确认命令行确实是 `tools/print_robot_receiver.py` 后再停止：

```bash
ps -fp <PID>
kill -TERM <PID>
sleep 1
ss -ltnp | grep ':19001' || echo '19001 已释放'
```

如果使用了 PID 文件，先检查文件内容再执行：

```bash
cat ~/.cache/robot-station/receiver.pid
ps -fp "$(cat ~/.cache/robot-station/receiver.pid)"
```

接收端已经在运行时，通常直接使用它即可，不要再启动第二个监听进程。重启接收端会让网关 TCP 连接断开；新进程启动后，在网页连接设置中点击“重新连接”。

## 6. Docker 部署

```bash
cp .env.example .env
# 编辑 .env，设置 ADMIN_PASSWORD 和实际机器人连接
docker compose -f deploy/docker-compose.yml up -d --build
```

容器内的 SQLite 位于持久化卷 `robot_station_data`。如果机器人运行在宿主机上，不能默认把 `ROBOT_HOST` 写成容器内的 `127.0.0.1`；应使用容器可达的宿主机地址或机器人局域网地址。反向代理部署时必须转发 WebSocket Upgrade，并使用 HTTPS。

## 7. 提交前检查

```bash
npm run typecheck
npm test
npm run test:integration
python3 -m py_compile tools/print_robot_receiver.py
```

集成测试会启动协议网关和测试接收端，验证控制租约、操作员权限、只读用户、机器人重连及停止清理。真机适配器还需要按照协议文档中的接入验收清单单独测试。

## 8. 目录说明

```text
apps/server/                  Fastify 网关、会话、人员管理、SQLite、TCP 桥接
apps/web/public/              实际运行的登录页、控制台、人员管理页和浏览器桥接脚本
packages/protocol/            ZRCP/1 类型、校验、长度分帧实现
tests/                        协议单元测试和网关集成测试
tools/                        打印接收端等联调工具
deploy/                       Dockerfile 和 Docker Compose
doc/                          协议设计、部署联调说明、历史界面参考
```

源码按运行职责分成 `apps`、`packages`、`tests`、`tools` 和 `deploy`，当前层级已经能对应构建和发布流程，不需要为了改名而移动目录。
