## 1. 系统边界与最小实现

```text
浏览器 H5                     普通 Web 后端                      机器人程序
HTML / CSS / JS   ⇄ HTTP/WS ⇄   配置、连接、协议适配   ⇄ TCP ⇄   协议服务 / 控制线程
                                                                   ↓
                                                        运动学 / 轨迹 / CAN / 驱动
```

Web 后端是 TCP 客户端，机器人程序是 TCP 服务端。一个控制通道对应一台机器人；v1 不在一个 TCP 通道里复用多台机器人。浏览器不接触 CAN、电机编号、编码器原始值或机器人认证密钥。

同机部署时，后端默认连接 `127.0.0.1:9000`；跨机器时连接机器人在局域网中的可达地址。端口 `9000` 是机器人 TCP 连接的默认值，可通过 `ROBOT_PORT` 或网页连接设置修改；网页服务默认端口是 `8080`，两者不是同一概念。仓库打印接收端的联调示例使用 `19001`，避免与真机默认端口混淆。

### 1.1 覆盖的操作

| UI 操作 | 本协议命令 | 必须实现的语义 |
|---|---|---|
| 连接与读取信息 | `system.hello`、`system.ping`、`system.describe` | 建立会话、查询能力、获得控制器单调时钟 |
| 读取反馈 | `state.subscribe`、`state.get` | 周期性完整快照、按需查询 |
| 启用 / 关闭控制 | `control.acquire`、`control.enable`、`control.heartbeat`、`control.release` | 单一控制权、短期授权、显式启用 |
| 松开当前按钮 | `motion.stop` | 停止指定动作，不自动关电机 |
| 停止全部 / Esc | `motion.stop_all` | 取消全部遥控动作并撤销控制授权 |
| 持续按住 / 目标执行中的保活 | `motion.keepalive` | 只续期已有动作，不创建动作 |
| 底座前后 / 原地转向 | `base.jog` | 前后速度或转向速度 |
| 身体升降 | `body.lift.jog` | 升降轴速度 |
| 身体前倾 / 后仰 | `body.pitch.jog` | 身体俯仰速度 |
| 腰部左转 / 右转 | `waist.yaw.jog` | 腰部旋转速度 |
| 左右手末端移动 | `arm.position.jog` | 指定坐标轴的线速度 |
| 左右手末端转动 | `arm.rotation.jog` | 指定坐标轴的角速度 |
| 精确定位 | `arm.move_to` | TCP 位置、姿态与速度上限 |
| 夹爪张开 / 闭合 | `gripper.jog` | 归一化开度变化率 |
| 头部转动 / 回正 | `head.jog`、`head.center` | 头部角速度；回到配置的正前方 |

### 1.2 Web 控制通道约束

浏览器连接 `GET /api/control` 的 WebSocket 只发送 Web 意图消息，不直接发送 ZRCP 帧：

```json
{"web_v":1,"type":"intent","id":"web-101","action":"base.jog","motion_id":"motion-1","params":{"linear_mps":0.1,"deadline_ms":100300}}
```

网关为每个连接单独保存控制租约。`control.enable` 会在服务端依次执行 `control.acquire` 和 `control.enable`；浏览器不接收机器人 `lease_id`。连续动作的 `lease_id`、`motion_id`、`seq` 和期限由网关注入或转发，停止优先。`motion.stop_all` 会清理连接状态，WebSocket 关闭、认证失效或页面失焦时也会尽力发送停止和释放租约。`viewer` 可以连接并接收状态，但任何意图都会得到 `FORBIDDEN`。

网关回复稳定的 `ack`，其中 `id` 原样回显浏览器请求，`command`、`motion_id`、`ok`、`code`、`msg`、`data` 对应 ZRCP 结果。机器人发送的 `state`、`event`、`result` 会作为 `robot_message` 推送给已认证连接；`robot_status` 用于连接状态变化。`msg` 只作为纯文本展示。

### 1.2 核心能力和可选能力

连接、鉴权、分帧、控制权、启用、停止、续期、状态反馈、超时与错误回复是**核心能力**。不能因为某机器人机械结构简单而省略机器人端的失联停机。

各个运动命令是**可选能力**。没有腰轴、没有升降、只有单臂、夹爪只支持离散开关，都可以接入。不支持某命令或某个 `arm/axis` 时，明确回复 `NOT_IMPLEMENTED`，UI 保留入口并提示，不虚构成功。

v1 限制**全机器人最多同时执行 1 个本协议运动任务**，包括底座、身体、末端、头部、夹爪。这与当前单按钮调试 UI 对应，可以避免上身运动与末端保持同时抢占控制。未来需要双臂联动、多轴组合或导航时再扩展，不能在 v1 中偷偷改变行为。

本协议不包含实体急停复位、电机强制上电、自动回零、保护旁路、示教编程、导航建图、相机视频或文件传输。网页“停止全部”是软件停止请求，不能替代硬接线急停。身体或机械臂需要保持力时，“停止”也不等于无条件切断电机使能。

## 2. TCP 传输与分帧

TCP 提供有序字节流，不保留应用层发送消息的边界；一次发送不对应一次完整接收。因此本协议自己分帧。[S1]

### 2.1 帧结构

```text
偏移 0             偏移 4
┌────────────────┬───────────────────────────────┐
│ uint32_be N    │ N 字节 UTF-8 JSON             │
│ 4 字节，大端序 │ 不包含 BOM，不追加分隔符      │
└────────────────┴───────────────────────────────┘
```

`N` 是 **JSON 编码后的 UTF-8 字节数**，不是字符数，不含前面的 4 字节。`1 ≤ N ≤ 65536`。接收方先取完整 4 字节，再取完整 N 字节；接收缓存中可能还有下一帧，必须继续解析。

例：`{"a":1}` 的 UTF-8 长度为 7，完整十六进制帧为：

```text
00 00 00 07 7B 22 61 22 3A 31 7D
```

这只是分帧示例，不是合法的 ZRCP 命令。

不使用换行符拆包，不通过括号计数猜测边界，也不把 `recv()` 返回值直接当成一个 JSON。TCP 连接可设置 `TCP_NODELAY` 以减少小包等待，但该选项不是分帧和超时机制的替代品。

### 2.2 编码和输入校验

JSON 使用 UTF-8，与 RFC 8259 的互操作要求一致。[S2] 本项目另外约定：顶层只能是对象；禁止重复键、`NaN`、`Infinity`、尾随非空数据和 BOM；嵌套深度最多 16；不识别的顶层扩展字段可忽略，但命令 `params` 中不认识的字段应拒绝为 `INVALID_ARGUMENT`，防止拼写错误悄悄生效。

非法长度、非法 UTF-8、无法完整解析的 JSON、超时未拼齐的帧：立即撤销该连接的控制权，停止相关遥控动作并断开。没有可靠 `id` 时不强行拼造请求回复。能够解析但缺少合法字段时，可以回复 `INVALID_MESSAGE` 后关闭控制通道；这不是 `NOT_IMPLEMENTED`。

### 2.3 连接与发送约束

握手必须在连接后 3 秒内完成。单帧从第一个字节到完整到达的设计期限为 1 秒；即使对端慢慢发送字节，也不能无限延长这个期限。运动超时独立计算，不能等分帧读超时才停。

发送采用有界队列；最新状态覆盖未发送的旧状态。停止消息优先于本机尚未写出的普通消息，但**不能超越已经进入 TCP 字节流的数据**，所以必须同时使用动作有效期和机器人端看门狗。不要在这条连接上发送图像、大文件或无界日志。

### 2.4 鉴权与网络暴露

v1 要求 `system.hello` 中的访问令牌，令牌由机器人端校验并映射到 `viewer` / `operator` 角色。`viewer` 只读；`operator` 可申请控制权和发出软件停止。

原始 TCP 本身不提供应用层身份认证或加密。本项目把握手令牌当作访问控制，不把它当作链路加密。跨主机正式使用时应部署 TLS 包装或受保护的专用网络隧道；开发阶段的明文仅限明确可信且隔离的实验网络，不直接暴露公网。连接目的地址由 Web 后端白名单限制；浏览器提交任意 IP 不应成为后端任意访问内网的通道。令牌不放入静态 HTML、URL、普通日志或浏览器本地存储。

## 3. 单位、坐标与方向

### 3.1 线上统一单位

| 量 | 协议单位 / 表示 | UI 显示 |
|---|---|---|
| 位置、高度 | m | mm |
| 线速度 | m/s | 底座 m/s，其余 mm/s |
| 角度 | rad | ° |
| 角速度 | rad/s | °/s |
| 夹爪开度 | `0.0…1.0` | `0…100 %` |
| 开度变化率 | ratio/s | 开度百分点/s，界面简写 `%/s` |
| 姿态 | 单位四元数 `[x,y,z,w]` | Roll / Pitch / Yaw |
| 时间、期限 | ms，单调时钟 | 通常不显示 |

换算：`m = mm / 1000`；`rad = degree × π / 180`；`ratio_per_s = 百分点每秒 / 100`。例如 60 %/s 在线上是 `0.6`，不是 `60`。

不得省略单位含义，不用一个 `speed: 20` 同时表示毫米每秒和度每秒，不发送只含 `normal/fast` 而没有物理速度值的机器人动作请求。

### 3.2 基座与末端

`frame: "base"` 表示机器人适配器给出的基座参考坐标系：X 向前、Y 向左、Z 向上，右手坐标系。它固定在底座上，不跟随腰部旋转；底座在世界中转动时，它随底座转动。坐标原点由机器人配置确定并在 `system.describe` 中说明，不从外壳形状推测。左右手始终以机器人自身为准。

v1 只要求 `base` 坐标系。不能把 `frame: "tool"` 当作 `base` 执行；不支持的坐标系返回 `FRAME_UNSUPPORTED`。

`position_m` 是当前配置工具的 TCP 相对 base 的位置，不是腕关节或法兰位置。`orientation_xyzw` 将工具局部向量旋转到 base：`v_base = R(q) · v_tool`。四元数必须为长度 4 的有限数字数组，范数与 1 的差不超过 `1e-3`；容差内允许归一化，越界或零范数拒绝。`q` 与 `-q` 表示同一姿态。

UI 欧拉角只用于输入与展示，换算约定：`R = Rz(yaw) · Ry(pitch) · Rx(roll)`。末端绕 base 轴的角速度不是直接让某个欧拉角按固定速度加减；例如绕 base X 转动使用 `q_new = dq_base_x · q_old`。接近奇异姿态时，欧拉角数值可能跳变，机器人端应使用自己的稳定旋转表示。

平移点动保持 TCP 姿态；转动点动保持 TCP 位置。做不到该约束时应拒绝，不能无提示退化成关节运动。

### 3.3 身体、腰部、头部和夹爪的正负

| 控制量 | 正方向 | 负方向 | 零位 / 参考 |
|---|---|---|---|
| 底座线速度 | 前进 | 后退 | 沿底座当前前向 |
| 底座角速度 | 从上向下看逆时针，即向左转 | 向右转 | 围绕底座竖直轴 |
| 身体升降 | 上升 | 下降 | 已配置升降机构的高度，不是总身高 |
| 身体 pitch | 前倾 | 后仰 | 已配置的直立参考，方向跟随腰部以上上身 |
| 腰部 yaw | 向机器人自身左侧转 | 向右侧转 | 上身相对底座的正前方 |
| 头部 yaw | 左看 | 右看 | 头部相对其安装父机构的正前方 |
| 头部 pitch | 抬头 | 低头 | 头部相对安装父机构的水平参考 |
| 夹爪变化率 | 张开 | 闭合 | 0 闭合、1 张开 |

**头部 pitch 的“抬头为正”是专门定义的人机语义，不是末端 RPY 中绕 +Y 的规则。** 不能直接复用末端姿态的符号。身体 pitch 也表示机构俯仰，不是整个机器人 TCP 的 pitch。

原始编码器零点、机械零点、安装方向由机器人适配层转换。头部“回正”是移动到已配置的正前方，不执行寻找限位、编码器清零或电机回零。身体升降/俯仰/腰部旋转会影响手和头的真实位姿，协议不承诺这些动作期间保持 TCP 不变。

## 4. 通用消息结构

### 4.1 五种消息

| `type` | 方向 | 含义 |
|---|---|---|
| `command` | Web 后端 → 机器人 | 一次请求 |
| `response` | 机器人 → 请求方 | 准入或查询回复，不代表运动完成 |
| `state` | 机器人 → 订阅方 | 完整反馈快照 |
| `event` | 机器人 → 已认证连接 | 控制权变化、故障等异步事件 |
| `result` | 机器人 → 动作拥有方 | 动作最终结果 |

本文所有 JSON 示例都是独立片段；示例 ID 和时钟值不可直接当成连续发送脚本。实际请求需生成唯一标识，并依据当前会话与时钟填写。

每个合法 `command` 有且只有一次逻辑 `response`。同一请求被幂等重传时可再次发送缓存回复，但不能再次执行副作用。`state/event/result` 不要求客户端再发 ACK。

### 4.2 请求结构

```json
{
  "v": 1,
  "type": "command",
  "id": "req-101",
  "session_id": "session-example",
  "command": "body.pitch.jog",
  "params": {
    "lease_id": "lease-example",
    "motion_id": "motion-example",
    "seq": 1,
    "deadline_ms": 100300,
    "velocity_radps": 0.1396263402
  }
}
```

| 字段 | 类型 | 规则 |
|---|---|---|
| `v` | integer | 当前只支持 `1` |
| `type` | string | 固定 `command` |
| `id` | string | 每会话唯一，1–64 个 ASCII 字符；建议 UUID；回复原样回显 |
| `session_id` | string | 机器人握手返回的会话 ID；仅 `system.hello` 不带 |
| `command` | string | 本文定义的命令名，区分大小写 |
| `params` | object | 即使没有参数也传 `{}` |

`session_id` 绑定 TCP 连接与鉴权身份，不能从另一个连接借用。机器人重启或 TCP 重连后重新握手，不复用旧会话和旧动作。

### 4.3 回复结构

```json
{
  "v": 1,
  "type": "response",
  "id": "req-101",
  "session_id": "session-example",
  "command": "body.pitch.jog",
  "robot_time_ms": 100000,
  "ok": true,
  "code": "OK",
  "msg": "已接受请求。",
  "data": {
    "motion_id": "motion-example",
    "phase": "accepted"
  }
}
```

成功是 `ok: true, code: "OK"`；失败是 `ok: false` 和相应稳定错误码。`msg` 是人读的说明，最大 512 个 Unicode 字符；UI 必须以纯文本显示，不能作为 HTML、脚本或错误类型判断条件。

`robot_time_ms` 是机器人当前进程/启动周期的单调毫秒时钟，不是 UTC 时间。`data` 始终为对象，无数据传 `{}`。所有后续回复回显 `session_id`；握手成功时该字段是新生成的会话。尚未建立会话的握手失败可以返回 `session_id: null`。

`accepted` 只说明校验通过并接受任务；不等于电机已经移动，不等于已到达目标。

所有时间戳、计数器和整数版本字段必须使用非负、可精确表示的 JSON 整数（不超过 `2^53−1`），动作 seq 另外受 `2^31−1` 限制。数字字符串不能代替数值字段。

### 4.4 ID、重试和乱序

Web 后端必须将浏览器请求 ID 与机器人请求 ID 分开管理，不能让两个浏览器的 `id=1` 相互覆盖。应匹配 `session_id + id + command`，运动结果另外匹配 `motion_id`。旧会话或已取消操作的迟到回复不得启动 UI 动作。

默认不自动重试带运动副作用的请求。需要重传时使用同一个 `id`、同一参数、原来的 `deadline_ms`，不能换 ID 或刷新期限伪装成新的点击。相同 ID 不同参数返回 `DUPLICATE_ID`。

机器人保留近期请求回复缓存至少 60 秒（建议上限 2048 条，过载时拒绝新请求），另保存本会话使用过的 `motion_id` 与关闭标记直到会话结束。若动作记录容量耗尽，应在停止后要求重连，不能删除记录后允许旧动作重启。即使回复缓存淘汰，过期命令、重复启动和已关闭动作仍由期限、动作 ID 及状态机拒绝。

## 5. 连接、查询与状态订阅

### 5.1 `system.hello`：建立会话

必须是连接上的第一个命令。除握手外的未认证命令不执行。版本数组中必须包含本端支持的版本；无交集返回 `VERSION_UNSUPPORTED` 并断开。

```json
{
  "v": 1,
  "type": "command",
  "id": "hello-1",
```

## 6. 控制权、启用与停止

### 6.1 状态机

```text
TCP 连接 → 握手已认证 / 只读
              ↓ control.acquire
           持有 lease / 未启用
              ↓ control.enable
           控制已启用 / 无动作
              ↓ motion start
           有一个动作在执行
              ↓ motion.stop / 正常完成
           控制已启用 / 无动作

停止全部、控制权失效、会话断开、动作看门狗超时、严重故障
    → 取消动作 + 撤销 lease + 回到已认证只读（或连接断开）
```

UI 的一个“启用控制”按钮可由后端内部完成“申请控制权 → 启用”两步，不需要新增两个界面按钮。

### 6.2 控制类命令

| 命令 | 参数 | 成功回复 `data` | 语义 |
|---|---|---|---|
| `control.acquire` | `deadline_ms` | `lease_id`, `lease_expires_ms` | 独占申请；不会抢占其他用户，不启动电机运动 |
| `control.enable` | `lease_id`, `deadline_ms` | `enabled:true` | 校验设备就绪、无急停/故障、状态新鲜；仍不运动 |
| `control.heartbeat` | `lease_id`, `deadline_ms` | `lease_expires_ms` | 延长控制权到处理时刻后 1000 ms，不延长动作 |
| `control.release` | `lease_id` | `{}` | 停止本 lease 动作、撤销 lease；需要重新申请 |
| `motion.stop` | `lease_id`, `motion_id` | `motion_id`, `stop_requested:true` | 关闭指定动作 ID，按控制器停止策略停下；保留控制权 |
| `motion.stop_all` | `{}` | `stop_requested:true`, `enabled:false` | 全部遥控动作停止并撤销当前 lease |

期限格式见第 7 节。只有已授权的 `operator` 可申请控制权；同一机器人最多一个 lease。冲突返回 `CONTROL_BUSY`，不得“最后连接的人自动接管”。已持有者重复申请的新请求也不偷偷换 lease，返回 `CONTROL_BUSY`；丢失原回复应使用原 `id` 查询缓存或释放后重来。

`motion.stop_all` 允许任一已认证 `operator` 发出，不要求它拥有正在使用的 lease；`viewer` 不可发出。这样另一位有操作权限的人能停止，但不能接管运动。只针对该控制台域所管理的动作；机器人自己的急停、安全系统和其他自主控制源应由更高层仲裁，不可假设网页能停止所有外部系统。

`motion.stop` 即使收到尚未开始的本会话 `motion_id`，也必须将该 ID 标为关闭；后到的 start/keepalive 不能将其复活。已关闭 ID 再次停止仍返回成功。停止 ACK 表示停止请求已接受，不证明机械体已经静止，最终看 `result` 与实际反馈。

停止命令不因为速度非法、机器人未启用或设备故障而被跳过。紧急情况下先切断遥控授权和目标更新，再执行设备支持的制动/保持策略。不能无条件把有重力负载的电机直接断电。

### 6.3 超时与失联

机器人控制线程以本机单调时钟独立检查：控制权期限、当前动作期限、设备反馈有效性和硬件故障。即使网络线程卡死或没有任何断开事件，也必须能触发停止。

默认：控制权心跳每 200 ms，授权期限 1000 ms；动作续期每 100 ms，每次动作有效期最多 300 ms。动作超时后，取消动作并撤销 lease。迟到的心跳、续期、响应都不能恢复控制，必须重新申请并启用。

这些时间只限制“多久发现命令不再有效”，不承诺机器人在 300 ms 内已经物理静止。实际停止时间和距离还取决于控制周期、减速度、机械状态与独立保护。

## 7. 连续动作与一次性目标的生命周期

### 7.1 每次新动作的公共参数

所有 `.jog`、`arm.move_to`、`head.center` 都携带以下字段：

| 字段 | 类型 | 规则 |
|---|---|---|
| `lease_id` | string | 当前已启用控制权 |
| `motion_id` | string | 本次按住或目标的唯一 ID，1–64 个 ASCII 字符；不可复用 |
| `seq` | integer | start 固定为 1；续期从 2 起严格增加，范围 `1…2^31−1` |
| `deadline_ms` | integer | 机器人单调时钟下的**绝对失效时刻**；必须大于当前时刻，且不超过当前时刻 + 300 ms |

新动作只能在当前无活动动作、状态有效、限位允许时被接受。另一个动作仍在执行时返回 `MOTION_BUSY`，不排队等待。UI 切换动作时应先停止旧任务，等停止被确认后再开始新任务；不能只在画面上抹掉旧任务。

每次新点击都使用新 `motion_id`；一次按住不重复发送 start。运动参数和速度在 start 时冻结，续期不能偷偷改方向或速度。

### 7.2 按住、续期、松开

```text
按下 → *.jog(seq=1) → response OK
继续按住 → motion.keepalive(seq=2,3,4...) 每约 100 ms
松开 → motion.stop(motion_id)
终态 → result(phase=stopped)
```

`motion.keepalive` 参数：`lease_id, motion_id, seq, deadline_ms`。成功回复 `data: {"motion_id":"...","phase":"running"}`，只延长已存在、未关闭、仍在同一 lease 中的动作。重复或倒退的 seq 返回 `STALE_SEQUENCE`，且不得刷新期限。未知或已关闭的动作返回 `MOTION_NOT_ACTIVE`，绝不当作 start。

准入 ACK 丢失或迟到时，不能根据“按钮还在按住”盲目新建一个任务。到请求期限仍无确认时，发送 stop 并撤销控制；观察状态确认结果。UI 已松开时，即使随后收到 OK，也只能继续确认停止，不恢复动作。

### 7.3 为什么用绝对期限，而不是“收到后再动 300 ms”

如果机器人每收到一条延迟很久的命令都从到达时刻重新计时，TCP 中积压的旧命令可能在用户松开后才开始执行。v1 因此用机器人单调时钟定义 `deadline_ms`，过期的命令即使第一次收到也拒绝，不能重新赋予完整有效期。

不要求机器之间的 UTC 时钟同步。Web 后端这样估算机器人时间：

1. 本机单调时刻 `b0` 发送 `system.ping`，`b1` 收到回复；回复带机器人发送前取样的时间 `s`。
2. 若 RTT `b1−b0 > 100 ms` 或该样本年龄超过 500 ms，关闭控制并重新取样，不继续发运动。
3. 在后端单调时刻 `b`，取保守估计 `robot_now_lower = s + (b−b1) − 5`。5 ms 是设计裕量，实施时结合时钟漂移和测试调整。
4. 新期限 `deadline_ms = floor(robot_now_lower + remaining_validity_ms)`，且 `remaining_validity_ms ≤ 300`。

这个估计不补上未知的回程网络延迟，因此通常缩短而不是延长命令有效期。若期限太短被机器人拒绝，就停下并提示链路不适合遥控，不靠无限加长期限掩盖问题。

**浏览器 → Web 后端也要有同样的防积压约束。** 第 12 节的 `bridge_time_ms/ui_deadline_ms` 在第一段链路作同类处理。后端把第一段剩余有效期转换成机器人期限，不能收到一条旧的网页消息后重新发满 300 ms。后台线程不得在用户已松开、窗口失焦或网页断联时继续替用户无限续期。

### 7.4 一次性目标也需要保活

`arm.move_to` 和 `head.center` 是一次性目标：用户不必一直按鼠标，但**网页必须在可见、连接有效且该目标仍被用户授权执行时发送 `motion.keepalive`**。切走页面、失焦、关闭弹窗后的明确停止、点击停止全部或断链时取消任务，不在后台继续执行。

提交目标后正常关闭输入弹窗不等于取消；此时只要页面仍可见、任务仍被授权，前端继续为目标保活。打开其他设置页或明确取消则停止。

目标拥有默认执行超时 30 秒，调用方可用 `timeout_ms` 指定 1000–60000 ms；控制器也可按自身限制拒绝。这个执行超时与每次 300 ms 的通信有效期是两回事。执行超时返回失败终态 `TARGET_TIMEOUT`。

目标正常到达后发出 `result`，不等待 UI 猜测数值已经接近。被拒绝的目标不会产生运动任务，不再发运动终态；已接受后规划/执行失败则必须发终态。

### 7.5 重连和切换

同一机器人同一时刻只保留一个活跃任务。切换速度档、左右手或移动/转动模式时，停止当前任务；用户下一次按下才应用新的选择。修改速度配置时关闭控制，保存后重新启用。TCP 重连、页面刷新、恢复前台都不恢复旧动作，也不默认恢复快速档。

|---|---|---|
| `arm` | string | `left` / `right` |
| `frame` | string | `base` |
| `position_m` | number[3] | TCP `[x,y,z]` |
| `orientation_xyzw` | number[4] | 单位四元数 |
| `max_linear_mps` | number | 正数，TCP 平移速度上限 |
| `max_angular_radps` | number | 正数，TCP 角速度上限 |
| `timeout_ms` | integer, 可选 | 1000–60000，默认 30000 |

v1 明确采用 base 中的直线位置路径，以及起始姿态到目标姿态的最短旋转插值；关节速度/加速度和奇异性限制可以使执行更慢。路径不可行时拒绝或失败，不能无提示切成绕障路径或关节空间大范围运动。机器人不能执行这类路径时回复 `NOT_IMPLEMENTED`，而不是把目标丢进任意关节规划器。

接受后仍可能因为实时状态变化而失败。到达判定使用机器人描述/配置中的位置和姿态容差，不要求浮点值完全相等。该命令不是夹爪抓取成功的证明。

### 8.8 夹爪开合：`gripper.jog`

`arm: "left"|"right"`；`velocity_ratio_per_s`：正张开、负闭合，非零。对 0–1 开度执行受限变化，到达开/合端点即正常停止，终态原因 `ENDPOINT_REACHED`。

## 9. 执行结果、状态与事件

### 9.1 动作终态：`result`

接受的每个动作最多产生一个逻辑终态。连接正常时必须推送；结果同时保留为状态中的 `last_result`，便于用户看到原因。连接丢失期间不能保证终态送达，因此 UI 应显示“执行结果未知 / 连接已断开”，而不是假装成功。

```json
{
  "v": 1,
  "type": "result",
  "session_id": "session-example",
  "request_id": "req-101",
  "motion_id": "motion-example",
  "command": "arm.move_to",
  "robot_time_ms": 102500,
  "phase": "succeeded",
  "code": "OK",
  "msg": "已到达目标。",
  "data": {}
}
```

| `phase` | 含义 | 示例 `code` |
|---|---|---|
| `succeeded` | 一次性目标完成，或夹爪达到正常开/合端点 | `OK` / `ENDPOINT_REACHED` |
| `stopped` | 用户松开或指定动作停止 | `USER_STOP` |
| `canceled` | 停止全部、释放控制权、被管理层取消 | `STOP_ALL` / `CONTROL_RELEASED` |
| `failed` | 失联、期限耗尽、设备故障或执行失败 | `COMMAND_EXPIRED`、`LIMIT_REACHED`、`IK_FAILED` 等 |

`motion.stop` 的 ACK 可以先于物理停止的 result；`motion.stop_all` 先撤销授权，再按控制器策略停止。成功查询或未实现拒绝不产生 `result`。闭合动作 ID 的续期一律拒绝。

### 9.2 全量状态：`state`

### 9.3 事件：`event`

```json
{
  "v": 1,
  "type": "event",
  "session_id": "session-example",
  "seq": 6,
  "robot_time_ms": 104200,
  "event": "control.revoked",
  "code": "STOP_ALL",
  "msg": "另一名已授权操作员停止了机器人。",
  "data": {
    "enabled": false
  }
}
```

事件名至少支持 `control.revoked`、`robot.fault`、`robot.description_changed`。`event.seq` 单独计数。控制权事件不公开其他连接的完整 lease 密钥；事件是提示，不替代下一次状态快照。

UI 只能将真实状态标为“反馈”。机器人接受请求不意味着数值已经改变；不得把输入目标直接写进“当前位置”。

## 10. 未实现与错误码

### 10.1 未实现的统一回复

```json
{
  "v": 1,
  "type": "response",
  "id": "req-101",
  "session_id": "session-example",
  "command": "body.pitch.jog",
  "robot_time_ms": 100000,
  "ok": false,
  "code": "NOT_IMPLEMENTED",
  "msg": "当前机器人未实现身体俯仰功能。",
  "data": {}
}
```

`NOT_IMPLEMENTED` 用于未实现命令、未配置机构，或命令实现只覆盖部分合法的 `arm/axis`。例如只有左臂时，右臂是本协议合法枚举但该机器人不支持，回复未实现。`arm:"third"` 则是非法参数，回复 `INVALID_ARGUMENT`。

UI 保留入口，收到后显示机器人 `msg`；该动作不开始、不更新假反馈、不自动重试、不在重连后补发。不因为一项未实现而禁用其他功能。重复提示应限流，不每次刷新都弹窗。可以在对应卡片下保留轻量说明，但不增加复杂能力配置页面。

`system.describe` 能让 UI 提前知道能力，但**不能代替每次动作的准入回复**。能力可能变化，机器人仍要明确回应。不使用“设备没反应”来推断未实现。

### 10.2 稳定错误码表

| `code` | 何时使用 | UI / 后端处理 |
|---|---|---|
| `OK` | 成功接受或查询 | 运动继续等反馈 / result |
| `NOT_IMPLEMENTED` | 本机没有该功能或合法子能力 | 提示，保持其他功能可用 |
| `VERSION_UNSUPPORTED` | 无共同协议版本 | 不启用，提示升级/适配 |
| `UNAUTHORIZED` | 未认证或令牌无效 | 不重试运动，重新认证 |
| `FORBIDDEN` | 角色无权限 | 提示权限不足 |
| `INVALID_MESSAGE` | 消息外形不合法 | 撤销控制并排查协议 |
| `INVALID_ARGUMENT` | 类型、枚举、字段或数值非法 | 不执行，提示检查输入 |
| `DUPLICATE_ID` | 同 ID 不同内容 | 协议错误，停止重发 |
| `CONTROL_BUSY` | 已有控制者 | 只读，不自动抢占 |
| `LEASE_EXPIRED` | 控制权已过期、已释放或被撤销 | 关闭 UI 控制，重新申请 |
| `NOT_ENABLED` | 有会话但未启用 | 提示先启用 |
| `NOT_READY` | 设备未就绪 | 只读，显示具体 msg |
| `NOT_HOMED` | 必要的机构基准/校准缺失 | 提示去设备端完成准备 |
| `EMERGENCY_STOP` | 实体急停有效 | 禁止运动，不从网页自动复位 |
| `ROBOT_FAULT` | 设备故障 | 关闭控制，显示故障 |
| `FEEDBACK_STALE` | 必需反馈无效或太旧 | 停止，等待恢复后重新启用 |
| `MOTION_BUSY` | 已有一个运动任务 | 不排队；先停止旧动作 |
| `MOTION_NOT_ACTIVE` | 未知/已关闭动作的续期 | 不重新启动 |
| `STALE_SEQUENCE` | 序号倒退或重复 | 不刷新期限 |
| `COMMAND_EXPIRED` | 已过绝对期限 | 不执行，关闭控制并检查链路 |
| `DEADLINE_INVALID` | 期限过长或不合法 | 不执行，检查时钟换算 |
| `SPEED_LIMIT` | 请求超出控制器允许速度 | 不执行，修改配置 |
| `LIMITS_UNAVAILABLE` | 无有效限制配置 | 不执行，设备端补充限制 |
| `LIMIT_REACHED` | 已到/将违反硬或软限位 | 拒绝或停止任务 |
| `FRAME_UNSUPPORTED` | 未支持坐标系 | 不按其他坐标系执行 |
| `TARGET_UNREACHABLE` | 目标或指定路径不可达 | 拒绝/失败，不能换路径偷跑 |
| `IK_FAILED` | 逆解失败 | 拒绝/失败，不伪造执行成功 |
| `SINGULARITY` | 无法安全处理奇异状态 | 停止并提示 |
| `COLLISION_RISK` | 控制器检测到碰撞风险 | 拒绝/停止，不绕过保护 |
| `TARGET_TIMEOUT` | 已接受目标超过总执行期限 | 失败终态，停止目标 |
| `RATE_LIMITED` | 请求过载 | 不累积重试；停止优先处理 |
| `INTERNAL_ERROR` | 未分类内部错误 | 停止相关任务，记录日志 |

`USER_STOP/STOP_ALL/CONTROL_RELEASED/ENDPOINT_REACHED` 是终态原因，不是运动 start 的成功准入码。未知错误码按失败处理并展示纯文本 msg，不默认当成成功。

“请求等待超时”与“机器人回复 `COMMAND_EXPIRED`”不同：前者是后端自身未收到确认，应该以本地 `ROBOT_TIMEOUT` 显示给网页，不伪造机器人已经回了某个错误。

## 11. 速度档配置

### 11.1 主界面和配置职责

主界面保留三个选择：**低速 / 标准 / 快速**，右侧只有一个“设置”入口。三档均可修改，标准和快速不再只是硬编码倍率。各机构单独定义速度，左右手共用同一组操作档位。

速度配置属于**控制台配置**，不是固件参数写入协议。当前页面把三档速度偏好保存在当前浏览器 `localStorage`，不会写入真实机器人；后端每次动作请求都会收到已经换算好的实际速度值。若以后改为按 `robot_id` 由 Web 后端保存，需要补充权限、版本冲突和机型切换规则，不能把某台机器人的快速档自动套给另一台。

机器人收到的是已换算的实际速度值。档位名字只服务于 UI，可记录到 Web 审计日志，不作为机器人计算速度的唯一依据。

### 11.2 配套 H5 的默认数值

下面是演示初值，**不是真机推荐值或安全承诺**。

| 设置键 | 部位 | UI 单位 | 低速 | 标准 | 快速 |
|---|---|---|---:|---:|---:|
| `base_linear` | 底座前后 | m/s | 0.15 | 0.30 | 0.45 |
| `base_angular` | 底座转向 | °/s | 15 | 30 | 45 |
| `body_lift` | 身体升降 | mm/s | 35 | 70 | 105 |
| `body_pitch` | 身体俯仰 | °/s | 8 | 16 | 24 |
| `waist_yaw` | 腰部旋转 | °/s | 15 | 30 | 45 |
| `arm_linear` | 末端平移 | mm/s | 40 | 80 | 120 |
| `arm_angular` | 末端转动 | °/s | 18 | 36 | 54 |
| `head_angular` | 头部转动/回正 | °/s | 18 | 36 | 54 |
| `gripper` | 夹爪开度变化 | %/s | 30 | 60 | 90 |

每一行要求有限正数，`低速 ≤ 标准 ≤ 快速`，允许相等。H5 额外有输入范围：底座前后 0.01–2 m/s、步长 0.01；底座/腰/末端转动 1–180 °/s；身体俯仰 1–90 °/s；头部 1–120 °/s；升降 1–300 mm/s；末端平移 1–500 mm/s；夹爪 1–100 %/s。除底座线速度外步长为 1。这些仅是原型输入边界，不能覆盖机器人真实上限。


`schema_version` 是 Web 配置版本，不是 TCP 线上的 `v`。`revision` 用于并发保存校验；UI 打开编辑时读到版本 1，保存时携带 `expected_revision:1`。版本冲突返回 HTTP 409，不覆盖另一位用户的更新。

当前页面使用 `localStorage` 键 `robot-console-preview.speed-profiles.v1`，内容为 `{version:1,profiles:{slow:{...},normal:{...},fast:{...}}}`，内部键是上表 UI 键，单位为表中显示单位。虽然键名保留了历史 `preview` 命名，它只保存当前控制台偏好，不代表机器人配置。存储失败时提示“仅当前页面有效”；读取损坏配置时回退默认值。

### 11.4 保存、切档与执行

保存是原子操作：27 个数值全部通过校验才更新，不能一半生效一半失败。“恢复默认”先填入默认值，仍需要按“保存速度”；取消不修改已保存设置。

打开速度设置即停止动作并关闭控制，保存后需要重新启用。每次打开 H5 从低速开始，不保存“控制已启用”状态，也不自动恢复快速档。切档时停止当前动作，不给正在执行的任务瞬间提速。

正式后端对已实现机构按 `system.describe` 校验速度上限；左右手共用档位时取两只已支持手臂/夹爪相应限速的较小值，头部取已支持轴的较小上限。不支持机构的配置可保留以便以后支持，但点击该机构仍由机器人回复 `NOT_IMPLEMENTED`。

若旧配置超过新机型或新限制，保留可编辑数值但标记无效，不发超限动作，不静默改成某个更小速度。机器人最终再独立检查一次，请求超限返回 `SPEED_LIMIT`。正常运动中因轨迹、加速度或关节约束降速是控制器行为，不等于接受非法速度上限。

### 11.5 速度如何进入命令

例如把“标准 → 末端移动”设为 60 mm/s，向上按钮产生：

```json
{
  "v": 1,
  "type": "command",
  "id": "req-101",
  "session_id": "session-example",
  "command": "arm.position.jog",
  "params": {
    "lease_id": "lease-example",
    "motion_id": "motion-example",
    "seq": 1,
    "deadline_ms": 100300,
    "arm": "left",
    "frame": "base",
    "axis": "z",
    "velocity_mps": 0.06
  }
}
```

向下使用 `-0.06`。精确定位复用该档的末端线速度和角速度作为上限；头部回正复用头部速度。夹爪、腰部和身体分别使用自己的配置，不相互代用。

原型的目标动画使用平滑插值，并按插值导数峰值放大持续时间，避免动画的瞬时速度超过设置值；这仍不是逆解、轨迹限加速度或真机可达性验证。

## 12. 常规 Web 前后端接口建议

本节给出可直接据此实现的最小桥接接口。TCP 机器人协议是上面的 ZRCP/1；Web 仍按常规 HTTP 配置 + WebSocket 消息处理，不让浏览器直接 TCP。

### 12.1 HTTP

| 方法 / 路径 | 用途 | 关键约束 |
|---|---|---|
| `POST /api/v1/robot/connect` | 请求后端连接指定机器人 | `{host,port}`；校验用户、目标白名单；后端从安全配置中取令牌 |
| `POST /api/v1/robot/disconnect` | 停止并断开当前机器人 | 先停止撤权；不能仅关闭浏览器面板 |
| `GET /api/v1/robot` | 读连接、描述、最近状态 | 返回 Web 链路与机器人链路的不同状态，不假装都连接 |
| `GET /api/v1/robots/{robot_id}/speed-profiles` | 读取速度配置 | 返回第 11.3 节 SI 配置对象 |
| `PUT /api/v1/robots/{robot_id}/speed-profiles` | 整体保存速度配置 | `{expected_revision,profiles}`；原子保存，校验单位/档位顺序/机型上限 |
| `GET /api/v1/control`（WebSocket 升级） | 实时意图与反馈 | 同源、校验 Origin、身份和角色；未认证不可操作 |

HTTP 通用成功 `{ok:true,code:"OK",msg:"...",data:{...}}`，失败 `ok:false`。参数错误 HTTP 400，未登录 401，无权限 403，版本/控制冲突 409，校验失败 422，机器人连接失败/未回复 502/504。不能 HTTP 200 后不带业务状态让网页猜。

一次部署只连接一台机器人也可以；换机前必须停止、撤销旧控制并重新握手。多个浏览器各有独立 Web 会话；后端为每个欲申请控制的 Web 会话分配独立的机器人 TCP 会话，或实施等价的严格映射，不能把所有标签页混在一个无身份的共享 lease 里。

### 12.2 WebSocket 消息与两段期限

Web 层不用机器人 TCP 的 4 字节长度前缀，一条 WebSocket 文本消息就是一个 JSON 对象。使用独立的 `web_v:1`，避免误把浏览器意图当成完整的机器人命令。

浏览器先发送 `type:"ping"`，包含唯一 `id`；后端回复 `type:"pong"` 并带 `bridge_time_ms`。取样方法与第 7.3 节相同，只是时钟双方换成浏览器 `performance.now()` 与后端单调时钟。所有可启动/续期的网页操作带 `ui_deadline_ms`，超过 300 ms 的未来期限或已过期请求都拒绝。停止请求不受动作期限约束。

```json
{
  "web_v": 1,
  "type": "ping",
  "id": "ping-ui-1"
}
```

```json
{
  "web_v": 1,
  "type": "pong",
  "id": "ping-ui-1",
  "bridge_time_ms": 50000
}
```

网页按下“左手上升”的意图示例（不是 TCP 原始帧）：

```json
{
  "web_v": 1,
  "type": "intent",
  "id": "ui-101",
  "motion_id": "ui-motion-1",
  "action": "arm.position.jog",
  "profile": "normal",
  "params": {
    "arm": "left",
    "axis": "z",
    "direction": 1
  },
  "ui_deadline_ms": 50300
}
```

后端查“这台机器人 / normal”的已保存 SI 速度，把 `direction` 的 ±1 乘以幅值，生成第 8 节的机器人请求。它分配机器人 `id` 和 `motion_id`，绑定浏览器原始 ID，填入自己的 `session_id/lease_id`，把第一段**剩余有效期**换成机器人 `deadline_ms`。不能信任浏览器随意提供的机器人 session、lease 或越权速度。

`profile` 必须是 `slow/normal/fast`。网页 `params` 白名单如下；除此之外不透传到机器人：

| `action` | 网页 `params` | 后端转换 |
|---|---|---|
| `base.jog` | `direction: forward/backward/left/right` | 选线/角速度，其余为零 |
| `body.lift.jog` | `direction: up/down` | 有符号升降速度 |
| `body.pitch.jog` | `direction: forward/backward` | 有符号身体俯仰速度 |
| `waist.yaw.jog` | `direction: left/right` | 有符号腰部速度 |
| `arm.position.jog` | `arm, axis, direction: ±1` | `frame:base` + 有符号线速度 |
| `arm.rotation.jog` | `arm, axis, direction: ±1` | `frame:base` + 有符号角速度 |
| `gripper.jog` | `arm, direction: open/close` | 有符号开度变化率 |
| `head.jog` | `axis, direction: ±1` | 有符号头部角速度，遵循第 3.3 节 |
| `arm.move_to` | `arm, position_m, orientation_xyzw`，可选 `timeout_ms` | 位置姿态直接校验；速度上限取档位 |
| `head.center` | 可选 `timeout_ms`，其余空 | 速度取头部档位 |
| `control.enable` | `{}` | 后端先 acquire，再 enable；无 motion_id/profile |
| `control.release` | `{}` | 停止并释放；无 motion_id/profile |
| `motion.stop` | `{}`，顶层必须有 `motion_id` | 停止该网页拥有的动作 |
| `motion.stop_all` | `{}` | 任一 operator 可停止；无 motion_id/profile |

所有 intent 都有唯一 `id`；运动 start 还有全新 `motion_id` 和 `profile`；enable/start 有 `ui_deadline_ms`。release/stop 无需期限。非法动作返回 `INVALID_ARGUMENT`；不能把任意字符串转发给 TCP。

按住期间或目标执行期间，网页每约 100 ms 发：

```json
{
  "web_v": 1,
  "type": "hold",
  "id": "ui-102",
  "motion_id": "ui-motion-1",
  "seq": 2,
  "ui_deadline_ms": 50400
}
```

hold 的 seq 从 2 开始严格增加。后端只在对应网页控制会话仍有效、用户未停止、UI 截止时间有效时转换为 `motion.keepalive`。即便 socket 还开着，连续 300 ms 没有新有效 hold 也撤权停止。网页还用每 200 ms 的 `type:"control_heartbeat", id, ui_deadline_ms` 证明控制页面仍在线，后端据此发送 `control.heartbeat`；它和 hold 各司其职，不能互相替代。

网页松开时发 `intent action:"motion.stop"`，停止全部发 `intent action:"motion.stop_all"`。后端处理停止后，关闭该 UI motion 映射，拒绝后到 hold。尚未下发机器人 start 的 UI 动作先被 stop 时，后端同样记关闭标志，防止工作队列稍后再发 start。

后端给网页的 ACK：

```json
{
  "web_v": 1,
  "type": "ack",
  "id": "ui-101",
  "motion_id": "ui-motion-1",
  "ok": true,
  "code": "OK",
  "msg": "动作已接受。",
  "data": {}
}
```

`ack` 必须对应实际机器人回复；后端连接失败或超时可自行回复失败，但不能伪造机器人已接受。非运动 ACK 的 `motion_id:null`。

反馈包装为 `{web_v:1,type:"robot_message",message:<机器人 state/event/result/response 对象>}`，后端在对外对象中移除 `session_id/lease_id`，把 `motion_id` 和结果的 `request_id` 映射为浏览器 ID。Web 层不把机器人访问令牌、其他用户 lease 或内部网络地址暴露给网页。

生产前端需要把前台可见、窗口焦点、真实按住状态、控制授权、请求关联和反馈新鲜度组合为允许续期的条件；定时器自己循环不等于用户仍在授权。浏览器后台页可能被节流，不能把网页定时器当成机器人端独立看门狗。[S4]

## 13. 完整时序例子

### 13.1 首次启用，按住腰部左转，然后松开

```text
Web 后端                          机器人
   ─ system.hello ───────────────→ 鉴权，生成 session
   ← response OK / session ──────
   ─ system.describe ────────────→ 描述与限制
   ─ state.subscribe(rate=10) ───→ 建立反馈订阅
   ← state ────────────────────── 新鲜状态，未启用
   ─ system.ping ────────────────→ 取机器人单调时钟
   ← response / robot_time_ms ───

用户点“启用”
   ─ control.acquire(deadline) ──→ 唯一 lease
   ← response OK / lease ────────
   ─ control.enable(lease) ──────→ 检查设备准备状态
   ← response OK ────────────────

用户按住腰部左转
   ─ waist.yaw.jog(seq=1) ───────→ 检查未实现、限速、授权、期限
   ← response OK / motion_id ────
   ← state / active_motion ──────
   ─ motion.keepalive(seq=2...) ─→ 仅延长这个动作
   ─ control.heartbeat ─────────→ 仅延长 lease

用户松开
   ─ motion.stop(motion_id) ─────→ 立即关闭动作 ID，开始停止
   ← response OK ────────────────
   ← result / stopped ─────────── 实际任务停止
   ← state / active_motion=null ─ 保留控制权，不再运动
```

`system.ping`、`control.heartbeat` 和 `motion.keepalive` 是三件事，任何一个不能替代另一个。

### 13.2 机器人没有身体俯仰

用户按前倾 → `body.pitch.jog` → `response ok:false code:NOT_IMPLEMENTED msg:...`。不创建 motion，不发 keepalive，不改反馈。UI 提示未实现，腰部、头部等其他已支持功能照常使用。

### 13.3 后端发完 start，网页就断了

后端发现 Web 断链/hold 到期 → 尽力发 `motion.stop_all` 并关闭授权。即使这条 stop 没到，机器人也依据 start 的绝对期限停止；迟到 keepalive 不得复活过期任务。页面恢复时重新获取状态并显式启用。

### 13.4 修改标准速度后操作

打开速度设置 → 停止并撤销控制 → 编辑标准档 → 整体校验/保存配置 → 回主界面 → 点启用 → 选标准 → 新动作带修改后的 SI 速度。已经开始的动作绝不热更新速度。

### 13.5 目标不可达

`arm.move_to` 参数合法但指定直线路径不可达：准入时可判断则 `response ok:false TARGET_UNREACHABLE`，不发 result；接受后规划/执行才失败则发 `result phase:failed`。UI 显示原因，不自动改走关节路径或降低约束后重试。

## 14. 分帧参考代码与执行线程边界

以下 Python 代码只实现本协议的 TCP 编解码，使用标准库，可以用于写测试客户端/服务端。它不是机器人控制器；没有认证、状态机、看门狗或任何运动执行逻辑。

```python
from __future__ import annotations
import json
import socket
import struct
import time
import math
from typing import Any

MAX_FRAME_BYTES = 65536
MAX_DEPTH = 16

class ProtocolError(ValueError):
    pass

def _object_pairs(pairs: list[tuple[str, Any]]) -> dict[str, Any]:
    result: dict[str, Any] = {}
    for key, value in pairs:
        if key in result:
            raise ProtocolError(f"duplicate key: {key}")
        result[key] = value
    return result

def _reject_constant(value: str) -> None:
    raise ProtocolError(f"invalid JSON number: {value}")

def _check_depth(value: Any, depth: int = 0) -> None:
    if depth > MAX_DEPTH:
        raise ProtocolError("JSON nesting too deep")
    if isinstance(value, float) and not math.isfinite(value):
        raise ProtocolError("non-finite JSON number")
    if isinstance(value, dict):
        for child in value.values():
            _check_depth(child, depth + 1)
    elif isinstance(value, list):
        for child in value:
            _check_depth(child, depth + 1)

def encode_frame(message: dict[str, Any]) -> bytes:
    if not isinstance(message, dict):
        raise ProtocolError("top-level JSON must be an object")
    _check_depth(message)
    payload = json.dumps(
        message, ensure_ascii=False, allow_nan=False,
        separators=(",", ":"),
    ).encode("utf-8")
    if not 1 <= len(payload) <= MAX_FRAME_BYTES:
        raise ProtocolError("invalid payload length")
    return struct.pack("!I", len(payload)) + payload

def _read_exact(sock: socket.socket, count: int, deadline: float) -> bytes:
    result = bytearray()
    while len(result) < count:
        remaining = deadline - time.monotonic()
        if remaining <= 0:
            raise TimeoutError("frame deadline exceeded")
        sock.settimeout(remaining)
        chunk = sock.recv(count - len(result))
        if not chunk:
            raise EOFError("peer closed the TCP stream")
        result.extend(chunk)
    return bytes(result)

def recv_frame(sock: socket.socket, frame_timeout_s: float = 1.0) -> dict[str, Any]:
    # One total deadline for header + payload, not a fresh timeout per recv().
    # A dedicated receive thread should own this socket's timeout setting.
    previous_timeout = sock.gettimeout()
    deadline = time.monotonic() + frame_timeout_s
    try:
        size = struct.unpack("!I", _read_exact(sock, 4, deadline))[0]
        if not 1 <= size <= MAX_FRAME_BYTES:
            raise ProtocolError("invalid payload length")
        payload = _read_exact(sock, size, deadline)
        if payload.startswith(b"\xef\xbb\xbf"):
            raise ProtocolError("UTF-8 BOM is not allowed")
        value = json.loads(
            payload.decode("utf-8", errors="strict"),
            object_pairs_hook=_object_pairs,
            parse_constant=_reject_constant,
        )
        if not isinstance(value, dict):
            raise ProtocolError("top-level JSON must be an object")
        _check_depth(value)
        return value
    finally:
        sock.settimeout(previous_timeout)

# Send from a single serialized writer, never interleave multiple frames:
# sock.sendall(encode_frame(message))
# Receiving callers must catch parsing, EOF, timeout and socket exceptions,
# then revoke control / stop through the robot's independent control logic.
```

参考接收函数对“调用后 1 秒无任何消息”也会超时；生产服务可以先等待可读事件，再启动从首字节开始的帧期限。不要因为这个 I/O 超时设计而改变 300 ms 的运动期限。

### 14.1 机器人程序内部建议

```text
网络读线程
  分帧 → 验证版本/身份/结构 → 校验期限/重复 → 有界命令交接区
                                                         ↓
机器人控制线程（自己的周期）
  先检查急停/设备反馈/控制权/动作期限
  → 处理最高优先级停止
  → 验证新动作及互斥
  → 运动学/轨迹/驱动执行
  → 发布带采样时间的状态快照
                                                         ↓
网络写线程
  有界回复与结果队列 + 最新状态覆盖 → 完整帧发送
```

同一安全相关状态必须有明确单一所有者或原子同步约束，不能让网络线程和控制线程各自认为自己拥有同一轴。运动规划任务不能长时间阻塞超时检查；取消必须能传入规划/执行环节。

网络线程不在收到 JSON 后直接写电机寄存器；Web 后端不以 TCP 连接正常代替驱动正常；UI 不自行计算并发送电机原始位置。

## 15. 接入验收清单

以下是后续真实实现必须通过的测试，不是声明当前 H5 已通过真机验收。

| 类别 | 必测情况 | 期望 |
|---|---|---|
| 分帧 | 长度头拆成 1/1/2 字节；正文任意拆分；多个帧一次到达 | 不丢帧、不合并错消息 |
| 编码 | 中文 msg；重复键；NaN；非法 UTF-8；超长帧 | 正常文本成功，非法输入拒绝并安全断开 |
| 鉴权 | 未 hello；错误令牌；viewer 发送运动 | 无任何电机动作 |
| 会话 | 两个 TCP 会话交叉使用 session / lease | 拒绝越权 |
| 控制权 | 两个客户端同时 acquire | 仅一个成功，不自动接管 |
| 未实现 | 身体俯仰不存在；只有左臂；头只有 yaw | 明确 NOT_IMPLEMENTED，其他功能可用 |
| 方向 | 所有正负按钮与真实机构逐项低速核对 | 与第 3 节一致，不只看软件数值 |
| 单位 | 60 mm/s；30 °/s；50 %/s | 分别转换为 .06、π/6、.5 |
| 速度 | 三档逐行配置；负数、空值、乱序、超限 | 配置原子拒绝；机器人最终独立拒绝超限 |
| 点动 | 按住、松开、指针移出、pointercancel、键盘松开 | 松开停止，不残留目标 |
| 延迟 | start 在截止时间后才到；stop 先于待处理 start | 过期/已关闭动作不执行 |
| 续期 | 丢 keepalive；重复 seq；旧 motion ID | 到期停止，不被迟到包复活 |
| 两跳 | 网页→后端积压，后端→机器人积压 | 不重新赋予完整期限 |
| 断链 | 拔网线、杀后端、关闭网页、仅网络线程卡住 | 控制线程独立停止并撤权 |
| 目标 | 精确定位期间失焦/停止；目标超时 | 任务可取消，终态与反馈一致 |
| 可达性 | IK 失败、指定路径不可达、奇异、碰撞风险 | 拒绝/停止，不偷偷换动作方式 |
| 限位 | 点动到升降/俯仰/腰/头/夹爪边界 | 受控停止；夹爪正常端点不报抓取成功 |
| 状态 | 状态断流；包新但硬件采样旧 | 显示未知/过期，不显示假正常 |
| 重连 | 旧 ACK/result 到新页面；恢复网络 | 不恢复旧动作，默认低速且未启用 |
| 设置 | 保存取消、恢复默认未保存、冲突 revision | 不意外覆盖或半生效 |
| 软件停止 | 当前操作者失联，其他 operator 点停止全部 | 接受停止并撤销原控制权 |
| 机械停止 | 测实际停止时间/距离、保持力、负载工况 | 达到项目自身风险评估要求 |

完成上述软件测试仍不等于实体急停、机械安全和应用风险已经通过认证；这些是独立工程工作。

## 16. 原型对应关系、兼容性与参考资料

### 16.1 当前仓库实现与历史原型

当前运行页面是 `apps/web/public/console.html`，通过同源 `bridge.js` 连接认证 WebSocket，再由后端连接机器人 TCP 服务。页面不再内置浏览器模拟机器人；按住按钮会持续发送动作保活，状态数值和动作终态来自机器人 `state` / `result` 消息。

当前仓库已实现：登录、角色和人员管理、审计、具名机器人连接保存与切换、ZRCP/1 分帧与校验、控制租约、连续动作保活、状态订阅、结果事件和刷新/断线清理。`tools/print_robot_receiver.py` 是只依赖 Python 标准库的联调接收端，会模拟一份内存状态并按约 10 Hz 推送反馈。

`doc/robot_console_v0.3.html` 是早期离线界面设计参考，保留用于视觉和交互追溯，不是运行页面，也不代表当前已经存在浏览器内模拟器。速度档目前保存在浏览器 `localStorage`；机器人连接配置和人员数据由 Web 后端保存在 SQLite。若未来把速度档改为服务端按机器人持久化，需要增加版本、权限和并发保存接口，不能把本地存储格式直接当成机器人协议。

### 16.2 从 v0.2 的变更

旧稿把 `params.speed` 写成 `slow/normal`，并给身体/腰部使用 `direction` 字符串，只覆盖新增功能。本完整稿整体替换该临时约定：机器人线上使用明确的有符号 SI 速度，增加会话、控制权、动作 ID、期限、续期、终态与完整状态。

UI 版本是 v0.3；文档是完整设计稿 v1.0；线上 `v` 仍为 1。旧稿从未冻结为已部署协议，因此这里不能声称与旧 v0.2 报文向后兼容。已有实验适配器需要显式升级，不能静默兼容猜测。未来一旦上线冻结，改变字段含义必须提升线协议版本；追加可选能力也必须通过描述协商。

### 16.3 页面来源与存储

正式页面必须由 Web 服务提供，不能把历史 HTML 文件直接用 `file:` URL 打开来代替控制台。当前页面依赖同源的 `session.js` 和 `bridge.js`，并通过 WebSocket 接收机器人状态；连接配置、用户、会话和审计由后端 SQLite 管理。速度档仍是浏览器侧偏好，保存在当前浏览器的 `localStorage`，浏览器隐私模式或存储策略可能导致它无法持久化。[S3]
